# 微信云开发联机部署（当前方案）

> 适用：**没有公网服务器、没有备案域名**，但要让手机 / 异地好友直接联机。
>
> 当前环境：`cloud1-d7g8xcknn7afb1637`
> 小游戏 AppID：`wx31c52de4c0526c31`
> 云函数：`gx13`
> 集合：`gx13_rooms`

---

## 1. 这套方案怎么工作

```
微信小游戏 A ─┐
微信小游戏 B ─┼─ wx.cloud.callFunction({ name:'gx13' }) ─→ 云函数 gx13
微信小游戏 C ─┤                                               │
微信小游戏 D ─┘                                          云数据库 gx13_rooms
                                                               │
                                     云函数只把「自己的手牌」返回给各自客户端
```

- 建房、加入、发牌、出牌、过牌、结算、进贡、AI 推进、超时、发言、改名、解散，全部在 `gx13` 里。
- 客户端每 800ms 调一次 `state` 拉状态；不需要 WebSocket，不需要域名，不需要服务器。
- 客户端**不直接读数据库**。`gx13_rooms` 里是整桌数据，云函数用 `viewFor` 裁剪后才返回，所以别把集合权限开成“所有用户可读”。
- 浏览器 `preview.html` 仍然走 WebSocket（只用于本地预览/测试），微信小游戏默认走云开发。

## 2. 首次部署（只需要做一次）

### 2.1 确认云开发已开通

1. 微信开发者工具打开 `E:\AAproject\guangxi_13\minigame`。
2. 点顶部「云开发」。
3. 如果已经能进入控制台，说明已开通；当前账号下已有环境：
   - `cloud1-d7g8xcknn7afb1637`
4. 如果还没有环境：创建环境（名字随意，例如 `gx13-prod`），把环境 ID 填到：
   ```js
   // minigame/js/config.js
   CLOUD_ENV: 'cloud1-xxxxxxxx'
   ```
   只有一个环境时可以留空，默认环境就是它。

### 2.2 上传云函数

在开发者工具左侧文件树：

```
minigame/
└── cloudfunctions/
    └── gx13/
        ├── index.js
        ├── package.json
        └── engine/
```

右键 `gx13` 文件夹 → **上传并部署：云端安装依赖**。  
第一次会安装 `wx-server-sdk`，等它完成；更新代码后重复这一步。

也可以用命令行（开发者工具已登录时）：

```powershell
D:\Tencent\微信web开发者工具\cli.bat cloud functions deploy `
  --project E:\AAproject\guangxi_13\minigame `
  --env cloud1-d7g8xcknn7afb1637 `
  --names gx13 `
  --remote-npm-install
```

### 2.3 建数据库集合、设权限

云函数第一次运行会自动尝试建 `gx13_rooms`。如果控制台里还没有：

1. 云开发控制台 → 数据库 → 新建集合 `gx13_rooms`。
2. 权限设成 **仅创建者可读写**，或自定义规则：
   ```json
   {
     "read": false,
     "write": false
   }
   ```
   云函数是管理员身份，能正常读写；普通客户端不能直接读，手牌不会泄漏。
3. 不需要建索引；房间号是 4 位随机数，按 `_id` 查。

### 2.4 云函数超时

当前 `gx13` 的超时是 **3 秒**。一局请求通常远低于 3 秒，但冷启动/进贡推进偶尔会顶到上限。  
建议在：云开发控制台 → 云函数 → `gx13` → 配置 → 超时时间，改成 **10 秒**。

### 2.5 重新编译

开发者工具点「编译」。进入游戏后：

- 大厅顶部的服务器胶囊应显示 **“云开发 cloud1-d7g8xcknn7afb1637”**（或“云开发 当前环境”）。
- 点「快速开局」应该直接发牌，不再出现“连不上服务器”。

## 3. 真机 / 两个账号联机测试

> 预览二维码只对项目成员/体验成员有效。异地好友测试前，先在 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 管理 → 成员管理里把对方加为体验成员，再让对方扫「体验版」二维码；正式发布后不再受此限制。

1. 开发者工具点「预览」，用手机微信扫码。
2. 手机 A 打开小游戏 → 开始游戏 → 创建好友房，记下 4 位房号。
3. 手机 B（另一个微信账号）打开小游戏 → 加入房间，输入房号。
4. 两边都应进入等待房；房主点「开始」，空位补机器人。
5. 测试以下动作：
   - 发言：右下角「发言」打开右侧浮层，不挡手牌；发一条文字/表情，两边都能看到。
   - 改名：牌桌内点昵称修改，另一边座位名同步。
   - 解散：房主在暂停菜单点「解散房间」，其他人回大厅。
   - 断线：手机 B 切后台再回来，应能通过 `rejoin` 回到原座位（同一 openid）。

> 手机和电脑不需要在同一个 Wi-Fi；云开发走微信官方网络。

## 4. 常见错误

| 现象 | 原因 / 处理 |
|---|---|
| 大厅红字“云开发初始化失败” | 开发者工具没开通云开发，或 `config.js` 环境 ID 填错 |
| “云开发调用失败，请确认 gx13 云函数已上传” | 云函数没上传到当前环境；重新执行 2.2 |
| `-501000` / `env not found` | `CLOUD_ENV` 与云函数所在环境不一致 |
| `permission denied` | `gx13_rooms` 集合权限或云函数权限异常；按 2.3 设为私有 |
| 快速开局一直“准备中” | 看云开发控制台 → 云函数 → `gx13` → 日志；多为超时或依赖没装好 |
| 两边不同步 | 确认两边都是新版本（大厅显示“云开发”），不要一边用 WebSocket 一边用云开发 |
| 手机能进但电脑不能 | 电脑开发者工具也要选同一个云环境，并重新编译 |

## 5. 费用与限制

- 云开发有免费额度，超出按量计费；本项目只有房间状态读写，4 人桌每 800ms 一次 `state`，费用很低，但**不是永久免费**。
- 云函数单次最长 20 秒；本项目默认 3 秒，建议改 10 秒。
- 房间文档在最后一个人离开 / 房主解散时删除；异常退出留下的空房间可能残留，可在控制台手动清，或后续加定时清理。
- 云开发不需要域名、备案、服务器、wss 证书；这是本方案相对自建 WebSocket 的核心优势。
- 浏览器预览页仍然要求本地 WebSocket 服务端，和线上小游戏无关。
