## 1. 这是什么

一款 4 人跑牌类扑克游戏，微信小游戏形态（不是普通小程序——见第 6 节）。

一句话：**每人 13 张，先出完牌的一方获胜；持黑桃 3 与黑桃 A 的两人暗中结为一队，若一人同持两张则 1 打 3。**

核心乐趣来自**身份隐藏**：你不知道另外三人谁是队友，只能靠出牌方式和让牌动作去猜、去暗示。这决定了整个交互设计——身份绝不能下发到客户端。

名字"广西十三张"已被多家商业棋牌产品占用，提审大概率判近似或侵权。对外名称建议用 **「十三张·独食」**，包名/小程序名避开"广西十三张"字样。

## 2. 规则规格 v1（待第 3 节确认）

### 2.1 牌与人数

| 项 | 规格 |
|---|---|
| 用牌 | 52 张，去掉大小王 |
| 人数 | 4 人，各 13 张，全部发完 |
| 发牌 | 服务端随机洗牌后逆时针发牌 |
| 出牌方向 | 逆时针 |

### 2.2 阵营

- 持 **黑桃 3** 的玩家与持 **黑桃 A** 的玩家为同一队，其余两人为另一队 → 2 打 2。
- 若同一人同时持黑桃 3 与黑桃 A → 该玩家**独食**，1 打 3。
- 身份对其他人不可见；**玩家自己只能从手牌推断自己的身份**（手里有黑桃3/A 就知道自己是"内线"）。

### 2.3 出牌流程

1. 首局由持 **方块 4** 的玩家先出，且**第一手牌必须包含方块 4**（默认，见 3.1）。
2. 后续每轮：下家可出**同张数、同牌型等级且更大**的牌，或选择"过"。
3. **连续三家过牌** → 最后出牌者获得新一轮首出权，可任选合法牌型。
4. 一方中**任一人先出完手牌** → 该方获胜，本局结束。

### 2.4 牌型与大小

牌型等级（小 → 大）：

| 等级 | 牌型 | 张数 | 比较键 |
|---|---|---|---|
| 1 | 单张 | 1 | 点数 → 花色 |
| 2 | 对子 | 2 | 点数 → 花色（按确认口径） |
| 3 | 三张 | 3 | 点数（是否允许待确认，见 3.3） |
| 4 | 顺子 | 5 | 最大张点数 → 该张花色 |
| 5 | 同花 | 5 | 最大张点数 → 该张花色 |
| 6 | 三带二 | 5 | 三条的点数 |
| 7 | 四带一 | 5 | 四条的点数 |
| 8 | 同花顺 | 5 | 最大张点数 → 该张花色 |

- **只有同张数才能比较**；5 张牌型可跨型比较，按上表等级（同花顺 ＞ 四带一 ＞ 三带二 ＞ 同花 ＞ 顺子）。
- 点数顺序：`A > K > Q > J > 10 > 9 > 8 > 7 > 6 > 5 > 4 > 3 > 2`
- 花色顺序：`黑桃 > 红桃 > 梅花 > 方块`
- 顺子边界：`A2345` 为最小顺，`10JQKA` 为最大顺；A 不能夹在中间（如 `JQKA2` 非法）。

### 2.5 结算（默认口径见 3.4）

按各人剩牌张数 `n` 计算赔付倍数：

| 剩牌 n | 倍数 |
|---|---|
| 1–7 | 1× |
| 8–10 | 2× |
| 11–12 | 3× |
| 13（一张未出） | 4× |

- **2v2**：负方两人各按自己的剩牌赔给胜方；胜方内部如何分配（头游独收 / 两人均分）待定，默认**头游独收**。
- **独食 1v3**：独食者先出完 → 三家各按剩牌赔给他；否则独食者按自己剩牌赔给三家各一份。

### 2.6 必须钉死的边界情况

这些是引擎最容易写错、也最容易在线下桌上吵架的地方，写代码前逐条定死：

1. **同点数对子比花色**：比"对子里较大的那张"的花色，还是先比较某张指定的？→ 默认：比较大那张。
2. **同花比较**：先比最大张点数、同则比该张花色（与顺子同口径），还是"先比花色再比点数"（大老二另一版本）？→ 默认：先点数后花色。
3. **三张（三条）是否可出**：独食公开规则里有"三张"，贵港十三张没有。→ 默认：**可出**。
4. **首手含方块 4 时，牌型是否受限**：方块 4 只能作为单张出，或可并入对子/顺子/同花一起出？→ 默认：可并入，只要包含方块 4。
5. **5 张牌型跨型压**：三带二能否压同花？（按等级表可以）→ 默认：可以。
6. **三家连过重开后**，是否仍要求含方块 4？→ 默认：不要求。
7. **一队中一人出完、队友还剩牌**：2v2 时队友剩牌是否计入赔付？→ 默认：**计入**，负方两人都按各自剩牌赔。
8. **独食者出完前，队友判定是否公开**：→ 默认：**结算时才公开身份**。

## 3. 待你确认（4 个默认 + 3 个补充）

### 3.1 首出牌是哪一张？【默认：方块 4】

- **方块 4** — 独食 / 横县找朋友的标准口径，与"黑桃3+黑桃A 组队"配套。✅ 当前默认
- **方块 2** — 贵港十三张的说法（你上一轮提到过）
- **方块 3** — 部分锄大地 / 大老二口径

> 这套规则判断会写成一个配置项 `FIRST_CARD`，改制只改一行，成本极低。

### 3.2 独食（一人同持黑桃3+A）怎么算？【默认：纯 1 打 3】

- **纯 1 打 3** — 照常出牌结算，不设投降/明牌。✅ 当前默认
- **投降或明牌** — 投降输一半，亮明两张牌赢双倍（竞技性更强，需额外 UI 与倍率逻辑）
- **重发牌** — 不设独食玩法

### 3.3 三条（三张）能否单独出？【默认：可以】

- 若"不可以"，则 3 张牌只能是三带二的一部分，牌型表少一档。

### 3.4 结算口径【默认：按个人剩牌张数】

- **按剩牌张数 ×1/×2/×3/×4**，独食者按 1 对 3 逐家算。✅ 当前默认
- **按队结算** — 胜队每人收、负队每人付，队内合并
- **只记胜负** — 不算倍数，只统计胜局与连胜

### 3.5 补充口径（默认已给，若无异议直接采用）

- 2v2 赔付归**头游独收**（另一种是队内均分）。
- 同花按"先点数后花色"比较。
- 首手含方块 4 时允许并入其他牌型。

## 4. 技术方案

### 4.1 形态选择

| 方案 | 说明 | 结论 |
|---|---|---|
| **微信小游戏 + 原生 Canvas 2D** | 牌类 UI 简单，包体小、冷启动快，不引引擎 | ✅ 采用 |
| 微信小游戏 + Cocos Creator 3.8 | 动效与场景管理省事，但包体大、首包压力大 | 备选（后期要做大量特效再换） |
| 普通小程序 + web-view 嵌 H5 | **违规**：游戏内容必须走游戏类目，会被驳回并封禁 | ❌ 不做 |

### 4.2 分层

```
┌ 渲染层  Canvas 2D：牌桌、手牌、动效、结算面板
├ 交互层  点击选牌 / 出牌 / 过牌 / 提示
├ 游戏核心（纯 TS，零引擎依赖）
│   ├ 牌型识别 hand.ts      （1/2/3/5 张 → 牌型 + 比较键）
│   ├ 合法性 check.ts       （能否压上家、首手约束）
│   ├ 阵营 camp.ts          （黑桃3/A → 2v2 或 1v3）
│   ├ 结算 settle.ts        （剩牌倍数、独食 1v3）
│   └ 状态机 table.ts       （回合推进、三家连过、结束判定）
├ AI 层   启发式出牌 + 让牌判断
└ 网络层  云函数发牌与校验 / 房间同步
```

**关键约束：游戏核心不 import 任何 `wx.*`、不 import 任何渲染代码。** 这样它能在 Node 里跑单测和自战，也能在浏览器里跑原型。

### 4.3 防作弊（牌类过审的硬要求）

- 发牌在**云函数**内完成，牌堆不下发。
- 客户端只接收：自己的 13 张 + 公共牌池 + 各家剩牌数。
- 每一手出牌由云函数**复算牌型合法性**，不信任客户端。
- 身份天然不泄露：客户端只知道自己的手牌，改包也看不到队友是谁。
- 断线重连：房间快照 + 重发全量状态。

### 4.4 AI

- 手牌拆解：把 13 张拆成"可出牌组"集合（单、对、三、顺、同花、三带二、四带一、同花顺）。
- 决策：能压就出**最小可压组**；手牌 < 6 张时切换"抢出"模式；队友身份未知时用"是否让牌"做启发式。
- 先做到"能陪人打完一局且不犯低级错误"，不做蒙特卡洛。

## 6. 上线路径与资质（必须先看清）

**扑克牌游戏不能作为普通"小程序"上架**：

- 小游戏一级类目固定为"游戏"，选了就不能改回。
- **个人主体不能选择"牌类"三级类目** → 个人号无法上线牌类游戏。
- 牌类**无论是否开通充值，都必须提交版号 + 软著**。
- 审核时效：IAA（无充值）13–37 个工作日。
- 运营红线：不得赌博玩法、不得付费房卡或抽头、**不得房间密码**、不得自定义头像昵称、不得世界聊天、不得赢家/充值排行、分享图不得展示计分结果。

因此：

| 路径 | 门槛 | 周期 | 适用 |
|---|---|---|---|
| **体验版**（开发者工具上传，加体验成员扫码玩） | 只要 AppID，不需类目/版号/备案 | 当天 | ✅ 先走这条 |
| 正式上架 | 企业主体 + 微信认证 + 软著 + 版号 + 备案 | 6 个月起，棋牌类版号通过率极低 | 后期再评估 |

体验版与正式版**代码完全一致**，资质齐了直接提审，不用重写——所以先做体验版不会白干。

## 7. 风险

1. **规则口径分歧**（方块4/方块2、三条能不能出、同花怎么比）——最大风险，靠第 3 节冻结 + 配置化消化。
2. **包体**：小游戏首包体积上限严格，牌面必须用图集，不能放整张 PNG。
3. **名字与侵权**：避开"广西十三张"商业名称。
4. **审核**：牌类过审极难，先把体验版跑稳，不要提前投入资质成本。
