# 十三张·独食 — 规则引擎自战验证报告

> 日期：2026-11-18　｜　规则版本：规则书 v0.8　｜　引擎：`engine/`（CommonJS + UMD 双兼容）
> 运行环境：Node v22.23.2（Windows 本地）

---

## 1. 这一步做了什么

把规则书 v0.8 落成**可执行的规则引擎**，然后用 AI 对 AI 自战跑满一万局，检查规则本身是否自洽。

引擎分层：

| 文件 | 职责 |
|---|---|
| `engine/cards.js` | 52 张牌、洗牌（可复现种子）、牌面标签 |
| `engine/rules.js` | 默认配置、5 套预设、**3 最大 4 最小**的点数序位、顺子表、进贡张数 |
| `engine/hand.js` | 牌型识别（单/对/三/杂顺/同花/三带二/四带一/同花顺）与比较 |
| `engine/camp.js` | 阵营判定（♠3 + ♠A 同队 / 一人同持=独食）、身份揭示触发 |
| `engine/moves.js` | 候选牌型生成、压牌筛选、手牌校验 |
| `engine/table.js` | 一局的回合状态机（首手♦4、过牌、三家连过重开、名次产生） |
| `engine/ai.js` | 启发式出牌：不轻易交 ♠3/♠A、能压就压、对手快走完时抢压 |
| `engine/settle.js` | 名次制计分（2v2 ±2/±1/0；独食 +6/+3/−3/−6） |
| `engine/tribute.js` | 进贡抽牌、♠3/♠A 亮牌归还重抽、还贡、先出权判定 |

## 2. 规则自检（`node test/selftest.js`）

**37 项全部通过**，逐条钉死规则书里容易吵的点：

- 点数：3 最大（13）> 2（12）> A（11）> K（10）> … > 4 最小（1）
- 单张：♠9 压 ♦9；但 ♦10 压 ♠9（先比点数）
- 对子：♦4♦4 是最小的一对，♠3♥3 是最大的一对，**♠9+♦9 压 ♥9+♦9**（比"较大的那张"的花色）
- 顺子：**A2345 最小、10JQKA 最大、JQKA2 不算顺**；`23456` 比大小只看 6
- 5 张跨型：同花顺 > 四带一 > 三带二 > 同花 > 杂顺
- 张数不同不可比；两对不同点、四张同点都不成牌型
- 进贡张数：胜方 1&2 → 重贡 4 / 轻贡 2；1&3 → 2 / 1；1&4 → 0
- 计分：2v2 ±2 / ±1 / 0；独食 +6/+3/−3/−6，且**每局分数总和恒为 0**

## 3. 一万局自战结果（`node test/selfplay.js 10000 8`）

**规模**：10000 局，每场 8 局连打（含第 2 局起的进贡），共 1250 场。

| 指标 | 结果 |
|---|---|
| 平均每局出牌步数 | **78.2**（含过牌），单局最多 101 步 |
| 独食局数 | **2354 局（23.54%）** |
| 2v2 名次组合 | 拿 1&2：2789（36.48%）／1&3：2507（32.81%）／1&4：2350（30.71%） |
| 独食者名次 | 第1 1185／第2 579／第3 364／第4 226 |
| 进贡执行 | 4643 次，平均抽 3.06 张 |
| ♠3/♠A 亮出重抽 | 606 次（约每 7.7 次进贡遇到 1 次） |
| 被抽最大牌原主人先出 | 4643 次（全部命中） |
| 卡死 / 非法出牌 / 名次异常 / 分数或手牌异常 | **0 / 0 / 0 / 0** |

### 3.1 两个数值可以反推校验

- **独食率 23.54% 是对的**。给定 ♠3 已在某人手里，♠A 落在同一人手里的概率是 `12/51 ≈ 23.53%`，实测 23.54%，吻合。
- **分数守恒 = 0**。名次制里 2v2 是 +2/−2、+1/−1、0/0；独食是 +6 对 −2×3、+3 对 −1×3……每局零和，一万局无一例外。

### 3.2 名次组合接近三等分

1&2、1&3、1&4 大致各占三分之一。这说明在当前 AI 水平下，**队友拿到一二名的概率和拿到一四名差不多**——不是规则问题，是 AI 没有协作。

---

## 4. 已知局限（别把自战结果当"强弱结论"）

1. **AI 没有队友意识**。真实的 2v2 里，队友会主动让牌（不压自己人、帮队友走），本引擎的 AI 是四个人各打各的。所以"独食者拿第一 50%"这类数字**不能**代表真实对局——真实桌面独食 1 打 3 是吃亏的，这里的独食者手里握着两张最大单牌，而三个对手不配合。
2. 自战只证明**规则不矛盾、程序不卡死、判分不溢出**，不证明平衡性。
3. 「刺激局」的剩牌倍数制只做了个占位实现（第 n 名 × 剩牌张数），规则书里这条还没冻结。
4. 独食变体倍数（叫独食 6 倍 / 暗独食 3 倍 / 摆牌独食 12 倍）仍未实现，规则书里也标着未查清。

## 5. 队友让牌 AI 对照实验（`node test/compare.js 2000`）

同一批 2000 副牌，分别由"各打各的 AI"和"信息受限的队友让牌 AI"各打一遍。

| 指标 | A 各打各的 | B 队友让牌 | 变化 |
|---|---|---|---|
| 独食者拿第一 | 51.9% | **58.7%** | +6.8 个点 |
| 独食者场均得分 | 2.93 分 | 3.45 分 | +0.52 |
| 2v2 拿 1&2（双下） | 39.8% | **44.3%** | +4.5 个点 |
| 2v2 拿 1&4（零分局） | 29.8% | 27.4% | −2.4 个点 |
| 过牌率 | 35.5% | 38.3% | +2.8 个点 |
| 平均步数 | 77.1 | 79.7 | +2.6 |
| 非法出牌 / 卡死 | 0 / 0 | 0 / 0 | — |

### 5.1 结论一：2v2 确实变强了

"双下"比例从 39.8% 升到 44.3%，零分局减少——队友开始互相让路、集中火力，这是让牌逻辑起作用的直接证据。

而且这个提升是**不对称**的：拿 ♠3 的那位，只要看见有人打出 ♠A 就知道对方是队友；而"手里一张身份牌都没有"的两个人，要等到 ♠3 和 ♠A **都被打出来**才能确认彼此。所以握着身份牌的一队在信息上先天占优。

### 5.2 结论二：独食者胜率反而涨了 6.8 个点

这一条与我事前的预判（"应该掉回 25% 左右"）相反，必须说清楚原因：

- 独食者一人握着 ♠3 和 ♠A，**打出任意一张，另外三家仍然不知道"我们仨是一队"**——他们只会认为"这人亮了身份，不是我的队友"。要等两张牌都亮过，他们才推得出"这是独食、剩下三个是一伙"。
- 在这段"信息真空期"里，三个对手按"互不信任"的模式打，会互相压牌、互相消耗；而独食者只需要对付三个各自为战的对手。
- 一旦三人都明白过来，独食者已经跑掉大半手牌了。

**这不是程序 bug，是规则本身的信息结构造成的。** 自战只是把它量化出来了。

### 5.3 由此引出的规则选择（需要你拍板）

| 方案 | 做法 | 效果 |
|---|---|---|
| A（现状） | 谁打出 ♠3/♠A 只亮自己 | 独食者占便宜，1 打 3 没那么难 |
| B | 独食者打出**第一张**身份牌时，系统公示"本局为独食" | 三家立刻结盟，独食变难，更接近真实牌桌 |
| C | 结算时才公开身份（谁都不亮） | 全程互相猜，最考演技，但线上难做（没人有耐心） |

我倾向 **B**：它是把"桌上大家看得出来"这件事显性化——真实牌桌上，一个人连出 ♠3 和 ♠A 两张，谁都知道他独食了，只是线上系统不吭声会显得别扭。

> **已拍板：采用 A（不公示）。** 房间设置键 `loneAnnounce` 默认关闭，保留开关备用。因此上面"独食者胜率 58.7%"是当前规则下的正常结果，不是需要修的错误。
