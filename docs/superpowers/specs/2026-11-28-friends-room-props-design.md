# 四人好友房：邀请、分享、房内道具 设计

日期：2026-11-28  
范围：只做“自己凑 4 个人”的熟人房，不做公开匹配、组队、任务、排位、赛事、观战。

## 1. 目标

- 一个人建好房后，能把 4 位房号用微信分享卡片/复制口令发出去，朋友点一下就能进同一个房。
- 房主能复制房号、邀请好友、踢掉等待中的陌生人、解散房间；其他人能准备/取消准备。
- 牌桌和等待房里有 3 个轻互动道具：砸蛋、西红柿、送花，带飞行动画和提示。
- 不引入道具库存、货币、商城、排行榜，避免把“熟人局”做成重运营游戏。

## 2. 非目标

- 不做公开匹配/房间列表/MMR。
- 不做组队、好友关系链、语音房。
- 不做每日任务、签到、成就、邮件、赛季、赛事、残局。
- 不做道具购买、数量、冷却以外的经济系统。
- 不做真实小程序码（首版先分享卡片 + 房号，避免云 OpenAPI 权限和图片存储）。

## 3. 现状与改动点

- 联机已经走微信云开发，房间/发牌/出牌/进贡/结算/聊天/改名/解散已有。
- `viewFor` 只返回裁剪后的状态，`chat` 已有 `{rel, kind, text, ts}`。
- 分享现在只有文案：`wx.shareAppMessage({title})`，没有房号 query、没有自定义图卡。
- 启动只有浏览器 `?room=` 解析；微信侧没有读 `wx.getLaunchOptionsSync().query.room`。
- 等待房有房号、准备、开始、解散，但没有复制房号、邀请按钮、踢人。
- 发言面板已有“表情/短语/打字”，没有道具页。

## 4. 方案对比

### 4.1 邀请方式

**A. 分享卡片 + room query（推荐）**

- `wx.shareAppMessage({ title, imageUrl, query: 'room=' + code })`
- 朋友点卡片 → 小游戏启动/`onShow` 读到 `query.room` → 自动打开大厅并 `join`。
- 同时提供“复制房号”按钮，发微信群/私聊都能用。
- 成本低、无需域名/二维码接口；缺点是分享卡片不是可扫码图片。

**B. 真实小程序码**

- 云函数调 `wxacode.getUnlimited` 生成带 `scene=room=1234` 的码，上传云存储，客户端展示/保存。
- 体验最好，但要开 OpenAPI 权限、处理图片缓存和过期，首版不值得。

选 **A**。房号本身就是口令；分享卡片 + 自动进房已经够四个人用。

### 4.2 房内道具

**A. 聊天事件 + 飞行动画（推荐）**

- 道具不是库存，是一次房间广播：`{t:'chat', kind:'prop', prop:'egg'|'tomato'|'flower', target: rel}`
- 云函数存进 `room.chats`，`viewFor` 返回 `{rel, kind:'prop', prop, target, ts}`。
- 客户端收到新事件后，从发送者座位飞向目标座位，700ms 动画 + 轻提示。
- 同一座位不设冷却，只受房间 30 条历史上限；不计数、不扣分。
- 目标用 3 个相对座位 chip 选择（西家/北家/东家），默认上一个目标。

**B. 道具库存/商城**

- 每个玩家有鸡蛋/西红柿/花数量，可购买/每日领取，带冷却和特效等级。
- 更像欢乐斗地主，但需要经济系统、防刷、 UI，和“四个人玩玩”的目标不匹配。

选 **A**。

### 4.3 房间管理

**A. 房号 + 邀请 + 踢人（推荐）**

- 不做房间密码：4 位房号 + 微信分享已经足够，密码会增加朋友进房摩擦。
- 房主在等待房可踢掉某个座位；对局中不允许踢人（避免破坏牌局）。
- 已有准备/开始/解散/离开保留。
- 房主离开自动移交，已实现。

**B. 密码 + 踢人 + 规则面板**

- 建房时设 4 位密码，加入时输入；再加局数/贡制/回合时间配置。
- 更完整，但熟人局用不上，且键盘输入会拉长进房流程。

选 **A**；规则沿用现有 8 局、重贡 20 秒。

## 5. 交互

### 等待房

- 顶部大字房号下方：
  - `复制房号`
  - `邀请好友`（微信分享，带 `room` query）
  - `分享房卡`（生成一张 600×800 图卡，含房号、玩法、4 个座位）
- 每个真人座位右侧，房主看到 `移除` 小按钮；机器人/空位不显示。
- 底部保留 `开始（空位补机器人）`、`解散房间`、`离开房间`。

### 对局中

- 右下角「发言」浮层新增第三个页签 `道具`。
- 道具页：
  - 第一行：目标 `西家 / 北家 / 东家`，当前目标高亮。
  - 第二行：`🥚 砸蛋`、`🍅 西红柿`、`💐 送花`。
  - 底部仍是 `✎ 打字发言`。
- 发送后本地立即回显一条 `你 砸了 西家 一个蛋`，并播放飞行动画；服务端 state 回来后按 `ts` 去重。
- 被砸/被送花的目标座位轻微抖动；如果目标是自己，手机轻震（受 `gx13_vib` 控制）。

### 分享图卡

- 结算页：本场得分、连胜、4 人座位名、房间号（如果还在房里）、`再来一局` 文案。
- 等待房：房号 + 4 个空位 + “还差 2 人” + 玩法名。
- 图卡用离屏 Canvas 画，`canvas.toTempFilePath` 生成临时文件；失败则退回系统默认分享图。
- 不做二维码；图卡上写“微信打开小游戏，输入房号 1234”。

## 6. 云函数改动

- `chat` 增加 `kind:'prop'`、`prop`、`target` 校验：
  - 只允许 `egg/tomato/flower`；
  - 目标必须是 1..3 的真人或机器人座位，不能是自己；
  - 不设冷却；房间 `chats` 只保留最近 30 条。
  - `chats` 条目加 `prop`、`target`。
- `viewFor` 的 `chat` 映射加 `prop`、`target`（都转相对座位）。
- 新增 `kick`：
  - 仅房主、仅 `phase==='wait'`；
  - `seat` 是相对座位，服务端转绝对座位；
  - 清空该座位，`lastEvent` 记录“房主移除了 X”；
  - 被踢者下一次 `state` 收到 `notInRoom`，客户端按 `roomClosed` 回大厅。
- 分享 query 不经过云函数；`room` 仍由 `join` 校验。

## 7. 客户端改动

- `app.js`：
  - `boot` / `onShow` 读取 `wx.getLaunchOptionsSync().query.room` 和 `wx.onShow` 的 `query.room`；如果当前不在房间，打开大厅并 `netJoin(code)`。
  - `shareRoom()`：`wx.shareAppMessage` 带 `query:'room='+code` 和 `imageUrl`。
  - `copyRoom()`：`wx.setClipboardData`。
  - `netKick(rel)`：发 `{t:'kick', seat:rel}`。
  - `sendProp(prop, target)`：发 `{t:'chat', kind:'prop', prop, target}`，本地回显 `pending`。
  - `track()`：关键事件埋点（进房、开局、完局、分享、道具），先走 `wx.reportEvent`，没有则忽略。
- `views/panels.js`：
  - 等待房加复制/邀请/图卡/踢人按钮和 hits。
  - 发言面板加“道具”页签、目标 chips、3 个道具按钮。
  - 新增 `drawPropFx`：从 `L.seats[SEAT_POS[from]]` 到目标座位插值，画 emoji + 小尾迹；由 `draw()` 在牌桌层调用。
  - `chatBubbles`/聊天列表把 prop 显示成“砸了 X 一个蛋 / 送了一束花”。
- `views/table.js` 或 `panels.js` 增加目标座位抖动，复用现有 `seatPlay` 类特效。
- `audio.js`：道具复用 `SFX.play('chat')`，不新增音频文件。

## 8. 验收

- 两台手机：A 建房 → 邀请好友 → B 点分享卡片自动进房；C/D 用复制房号加入。
- 4 人等待房：房主复制房号、踢掉一个座位、重新邀请；其他人准备/取消。
- 开局后：A 对 B 砸蛋、对 C 西红柿、对 D 送花；四台设备都能看到飞行动画和文字。
- 连续点道具：不会报错，也不会超出房间 30 条历史上限；不会刷屏到影响手牌。
- 结算页分享图卡能生成；生成失败时有系统分享兜底。
- `node tools/cloud-feature-test.js` 增加 prop/kick 用例；本地 fake wx 的 `net-cloud-test` 增加 prop 协议。
- 线上：重新部署 `gx13`，手机跑完整一局；不出现 `roomMissing` 误报。

## 9. 已确认

1. 邀请首版只做“分享卡片 + 房号自动进房”，不做真实二维码。
2. 道具只做“动画 + 文案”，不做库存/数量/商城。
3. 房间管理首版不做密码，只做复制房号、邀请、踢人。
4. 道具不设冷却。
